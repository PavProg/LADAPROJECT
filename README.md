# Краткая сводка по созданию веток и пользованию

## Работа с ветками

Все новые функциональные возможности разрабатываются в **отдельных ветках**.  
Ветки именуются по шаблону `features/НазваниеФичи` (например, `features/RigidBody`).

**Важно:** каждая ветка подразумевает внесение изменений в соответствующие папки проекта, а не создание новых корневых каталогов. Например, при работе над физическим телом (`RigidBody`) вы будете изменять файлы в папке `actors/player`:

actors/player/
├── RigidBody.gd # скрипт физического тела
├── player.tscn # сцена игрока
└── ... # другие файлы, относящиеся к игроку


Таким образом, архитектура фичи остаётся локализованной в своей директории, что упрощает поддержку и контроль версий.

### Основные команды Git для работы с ветками

```bash
# Создать новую ветку и переключиться на неё
git checkout -b features/НазваниеФичи

# Переключиться на существующую ветку
git checkout features/НазваниеФичи

# Отправить ветку на удалённый репозиторий и настроить отслеживание
git push -u origin features/НазваниеФичи

# Слить изменения из основной ветки (main) в текущую (перед созданием PR)
git pull origin main

После завершения работы и солгасования с участниками команды создаётся Merge Request (Pull Request) для вливания изменений в ветку main.
```
### Структура папок и файлы-заглушки

Git не отслеживает пустые папки. Чтобы они появились в репозитории, в каждой директории необходимо разместить хотя бы один файл.
В качестве такого файла используется README.md – он выполняет две функции:

	Заглушка – позволяет загрузить папку на GitLab.

	Документация – в этом файле кратко описывается содержимое папки, назначение скриптов, примеры использования и особенности отладки.

Рекомендация: для каждого важного скрипта (например, RigidBody.gd) создавайте рядом с ним README.md (или используйте общий файл в папке) с описанием:

	Что делает скрипт.

	Какие методы и свойства доступны.

	Как подключить его к сцене (если способ отличается от стандартного).

	Как отлаживать и на что обращать внимание.

Пример для actors/player/README.md:

# Компонент RigidBody

Данный скрипт реализует физическое поведение игрока.
- Основные параметры: масса, трение, сила прыжка.
- Подключение: добавьте узел RigidBody в сцену `player.tscn` и прикрепите скрипт.
- Отладка: включите `Visible Collision Shapes` в редакторе для визуализации коллизий.

### Ассеты

Все ассеты (модели, текстуры, анимации, материалы, шрифты и т.д.) хранятся в папке models.
Для анимаций предусмотрена вложенная папка models/animations.

Основной формат ассетов – .tres (текстовый ресурс Godot).
Преимущества:

	Хранятся в читаемом для человека текстовом виде (удобно для просмотра и правки).

	Отлично подходят для контроля версий – изменения видны в diff'ах.

    Поддерживаются встроенными средствами Godot.

Пример структуры:

models/
├── materials/
│   └── player_skin.tres
├── animations/
│   └── walk.tres
└── fonts/
    └── main_font.tres
